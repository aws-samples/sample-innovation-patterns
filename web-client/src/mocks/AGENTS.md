# mocks/

Shared MSW handlers + the browser worker. Used in dev (mock-UX mode) **and** tests.

**You are in mock-UX mode when `config.MOCK_API === true`** (`window.__CONFIG__.MOCK_API`).
In that mode the browser worker serves every `/api/v1/*` call from `handlers.ts` — no backend.

- When you add a page that fetches data, **add its handler here in the same change.** A page without a handler shows a network error in mock mode.
- Use **relative** URLs (`/api/v1/...`), never absolute. Relative paths match both the browser origin and the jsdom test origin.
- A handler's response shape **must mirror the matching app-lib DTO** (`routes/{name}_dto.py`) so `npm run codegen` produces a client that drops in when `MOCK_API` is flipped off. The handler is the API contract.
- Tests import `handlers` from here via `src/test/msw/server.ts` — keep this set the source of truth. Do not fork a second handler list.
- Do **not** edit `public/mockServiceWorker.js` — it is generated by `npx msw init public/` (run in `postinstall`) and gitignored.

See README.md for the three-stage UX-first loop and the mock→real migration recipe.
